# S3 独立供电时的对话记录

## 记录边界

- 每次“小爱同学”唤醒只创建时间标记，不将原始声音或持续麦克风数据写入 Flash。
- 有道识别文字与 DeepSeek 回复构成一条对话。DeepSeek 流结束时立即封存这条记录，后台存储任务只提交这一份不可变副本；不会追加之后的环境声音、空闲日志或语音播放日志。
- 流式回复中断标为 `deepseek_partial`；断网、ASR 失败、无有效回答、无后续语音、内存不足或队列满会以相应结果结束。下一次唤醒是新记录。
- 固定指令也会单独记为 `fixed_command`，它并不代表家电已经执行成功。
- 没有拦截全局串口日志，不保存请求头、Wi-Fi 密码、API 密钥或原始录音。已关闭每秒麦克风幅度诊断。

## 存储与掉电

- 原 `storage` 分区地址 `0x410000`、大小 2 MiB 不变；仅将其前 1 MiB 保留给原始循环日志，禁止同时把这一区域挂载为 SPIFFS。后 1 MiB 不写入。
- 64 个 16 KiB 槽位，写满覆盖最旧记录。每条最多保存问题的 2048 UTF-8 字节、回答的 8192 UTF-8 字节，超长截断不拆分 UTF-8 字符。
- 记录包含递增序号、开始/结束时的开机毫秒数、可用时的 Unix 开始时间，以及结果类别。未完成对时时 Unix 时间为 0。
- 头和正文分别做 CRC32，正文写入并读回校验后才写提交标记。只有完整、校验通过的记录会导出。
- 回复结束后还有很短的 Flash 提交时间。看到 `CHATLOG_SAVED ... recording=stopped` 才代表已落盘。使用充电头时无法看这个提示，建议问完后至少等 15 秒再断电；网络慢时可能需要更久。
- 仍在识别/请求中的对话只在 RAM 中，断电会丢失；写入中掉电可能损失当前槽位。模糊或未知存储头会让日志进入只读保护，仍可导出其他完整记录，不自动格式化。
- 这些是未加密的本地对话文字，拿到设备或导出文件的人可以读取。循环覆盖不等同安全擦除。

## 接回电脑导出

先关闭占用串口的监视器，在电脑运行（端口变化时修改 `--port`）：

```powershell
& 'G:\Espressif\tools\python\v5.4.4\venv\Scripts\python.exe' 'E:\系统默认\文档\ChatGPT\猫\conversation_logs.py' dump --port COM4
```

结果保存在项目 `diagnostics` 下新的时间戳 JSON 文件，旧文件不覆盖。导出不会删除板上记录；脚本打开串口时不主动复位。即使接线导致复位，已提交记录仍应保留。

串口命令使用换行结尾：`LOG_DUMP` 导出，`LOG_STATUS` 查询数量/是否可写。`LOG_SELFTEST` 仅新增一条明确标记的存储自检记录，不录音、不请求云端。正常使用无需自检命令。

## 验证

格式测试涵盖空白存储、中文、环形顺序、未提交记录、损坏数据、错误头、导出不完整等 11 项；这些是电脑端格式检查。另保留原有协议向量测试。

设备烧录、重启保留及真实对话边界的实测结果另记于 `diagnostics`，不得仅凭编译成功声称实际断电或真人对话测试通过。
